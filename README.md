# Mugen — endless multiplayer tower

[![License: MIT](https://img.shields.io/github/license/benjamincanac/mugen?color=black)](https://github.com/benjamincanac/mugen/blob/main/LICENSE)
[![Nuxt](https://img.shields.io/badge/Nuxt-black?logo=nuxt&logoColor=00DC82)](https://nuxt.com)

An endless multiplayer dungeon-crawl tower built with **Nuxt** and **[TresJS](https://tresjs.org)** on the [Vercel Functions WebSockets](https://vercel.com/docs/functions/websockets). Spawn in the hub plaza, gather your party, step onto the glowing teleport circle, and descend: every floor is a biome — weathered stone, sunken depths, verdant maze, magma halls — with its own hazards, rising difficulty, and a daily leaderboard chasing **depth**. Die to a trap and you're back in the hub, starting over.

Everything is simulated by an **authoritative game loop inside a Vercel Function** and fanned out over one WebSocket per player. No database, no game engine backend, no image assets — the world, the stone textures, and the 3D models are all generated by code.

> [!NOTE]
> WebSockets in Vercel Functions are in [beta](https://vercel.com/docs/release-phases#beta).

## Run it

```bash
pnpm install
pnpm dev
```

Open `http://localhost:3000` in **two browser tabs**. Move the mouse to look around (click captures the pointer; `F` goes fullscreen); `WASD` to move and strafe; `Space` to jump — active traps can be cleared mid-air; `Shift` to dash; `M` for the fogged tower map; `Enter` to chat.

## The game

- **The hub** — an open torch-lit plaza where everyone spawns and can group up. At its center, a rotating runic teleport circle: step on it and you're taken to floor 1.
- **Floors** — each floor is a maze with 2-tile-wide corridors, one biome per depth: Stone Dungeon (spike traps), Sunken Depths (geysers, knee-deep water that slows you), Verdant Maze (snapping vines, thick green fog), Magma Halls (eruption vents, glowing floor cracks) — then deeper, larger, denser again. The floor's exit portal drops you to the next one.
- **Stakes** — hazards cycle on timers everyone can read; touching an active one kills you and resets you to the hub. Depth must be re-earned.
- **Leaderboard** — deepest floor reached today, plus the fastest clear per floor.
- **Tower map** (`M`) — a live spectator view of every floor with markers for every runner, like a broadcast overlay. Both it and the WoW-style minimap are **fogged**: only tiles you've explored are revealed, so the maze stays a maze.
- **Sky** — a full day/night cycle and drifting weather (clear → overcast → rain), shared by all players via the server clock.

## How it works

Nitro v3 ships native [crossws](https://crossws.h3.dev) WebSocket support that works identically in dev and on Vercel, so a single `defineWebSocketHandler` ([`server/api/ws.ts`](server/api/ws.ts)) powers every environment.

### The tower never goes over the wire

Every floor is generated deterministically from **(UTC date, floor index)** ([`shared/utils/maze.ts`](shared/utils/maze.ts)): layout, hazards, spawn, and exit. Server and client build identical floors on demand — the server for collision and kills, the client for rendering, prediction, and the all-floors tower map. The world is the same across function instances and restarts all day, and rolls over to a fresh tower at midnight UTC.

### Authoritative simulation, client-owned heading

Clients send held keys (forward/back/strafe), one-shot jump/dash actions, and their mouse-look heading; the 20 Hz loop in [`server/utils/game.ts`](server/utils/game.ts) runs full shared kinematics — wall collision, gravity, jumping, dashing with cooldown, and prop ledges you can climb (solid props are part of the deterministic floor plan, so elevation is authoritative) — plus trap kills (only near the ground: jumps clear them), floor transitions, and per-floor clear records, broadcasting 10 Hz snapshots of players that moved. Positions are never accepted from clients, so leaderboard depth can't be faked; heading is client-owned because mouse-look must feel instant and can't be exploited.

### Third-person prediction

The camera follows a locally predicted self: held keys are integrated with the *same* shared `moveWithCollision` the server runs, blended toward the authoritative position ([`app/components/MazeScene.vue`](app/components/MazeScene.vue)). The camera boom shortens when a wall would block the view.

### Onboarding & identity (no database)

New arrivals hit a gate ([`app/components/CharacterGate.vue`](app/components/CharacterGate.vue)) to type a name, pick a character in a live turntable preview ([`CharacterPreview.client.vue`](app/components/CharacterPreview.client.vue)), and choose an accent color; pressing Enter drops them into the hub. Submitting `POST /api/auth` sanitizes the choice and sets an HMAC-signed, `HttpOnly` cookie holding `{ id, name, color, character }` ([`server/utils/session.ts`](server/utils/session.ts)) — no passwords, no database. The socket opens only after that; the cookie rides the same-origin WebSocket upgrade, and [`server/api/ws.ts`](server/api/ws.ts) verifies it to build the player instead of a random identity. So reconnects (frequent on Vercel) restore the *same* runner, and returning visitors skip the gate (`GET /api/auth`). The cookie is tamper-evident: a mangled signature is treated as unauthenticated.

### Art from code (plus a CC0 ruin or two)

- **Textures** — brick walls, cobblestone, moss, magma cracks, and the runic teleport circle are all drawn onto canvases at runtime ([`app/utils/textures.ts`](app/utils/textures.ts)).
- **Characters** — each runner **picks** one of six fantasy characters (plus an accent color) during onboarding; the choice rides the snapshot. They're composed from Quaternius' CC0 *Universal* packs by [`scripts/convert_universal_characters.py`](scripts/convert_universal_characters.py): an outfit from *Modular Character Outfits – Fantasy* (peasant / ranger, male / female), a head from *Universal Base Characters* trimmed to the neck with a mix-and-match hairstyle, and a shared clip set drawn from *Universal Animation Library* 1 & 2. All four packs are CC0. Because every base body, outfit, and animation shares one 65-bone "universal" skeleton, the clips ship once in `animations.glb` (skeleton only, no mesh) and bind to every character by bone name with no retargeting; the accent color dyes just the outfit cloth at runtime. Idle/Run/Jump/Roll are driven by movement state — including remote players, whose dash flag rides the snapshot.
- **Architecture & props** — floor slabs, arches, buttresses, columns, torches, statues, and clutter come from [Quaternius](https://quaternius.com)' CC0 *Ultimate Modular Ruins Pack*, converted from `.blend` to GLB by [`scripts/convert_props.py`](scripts/convert_props.py) (~2 MB total). Structural modules render as `InstancedMesh`es with per-biome tints; the hub is dressed by hand (colonnade, rails, ruined curved walls, statues) and floors get deterministic biome-flavored placement from the same seeds as everything else.
- **Geometry** — each floor's walls are a single three.js `InstancedMesh`; fog, sun, and rain particles are driven by the shared clock.

## Architecture

```
app/
├── pages/index.vue           # HUD: floor status, leaderboard, toasts, death flash, chat
├── composables/useGame.ts    # connection, reconnect, state, records, clock sync
└── components/
    ├── GameScene.client.vue  # Tres canvas + pointer lock, WASD, arrow fallback
    ├── MazeScene.vue         # 3D world: floors, biomes, sky/weather, hazards, players
    └── SpectatorView.vue     # live tower map of every floor

shared/
├── types/game.ts             # wire protocol
└── utils/maze.ts             # hub + floor generation, hazards, biomes, collision

server/
├── api/ws.ts                 # /api/ws — one crossws handler everywhere
└── utils/game.ts             # authoritative tick loop: movement, deaths, clears, records
```

## Reconnects

Connections close when a Vercel Function reaches its [max duration](https://vercel.com/docs/functions/limitations#max-duration); the client reconnects with exponential backoff and re-enters as a fresh runner in the hub. A `ping`/`pong` heartbeat detects half-open sockets client-side and doubles as a keepalive server-side.
